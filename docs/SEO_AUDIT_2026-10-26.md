# SEO AUDIT: TokoM, situs Hostinger

Date: 2026-10-26 (Asia/Jakarta)

Input received: repository lokal, situs staging Hostinger yang digunakan dalam percakapan, screenshot skor Hostinger tanggal 24 Oktober 2026, dan tujuan SEO untuk pembeli serta calon pengguna aplikasi melalui halaman berbeda.

Situs yang diperiksa: https://midnightblue-barracuda-463745.hostingersite.com/

## Batas audit

Pemeriksaan situs dilakukan sebelum perubahan merek lokal menjadi TokoM. Temuan situs aktif tidak otomatis menggambarkan kode terbaru yang belum diterapkan ke hosting. Browser terisolasi dan permintaan HTTP publik digunakan tanpa login atau mengubah data. Alat pembaca web tidak dapat mengakses domain ini, tetapi browser dan curl berhasil, sehingga kegagalan alat tersebut tidak dipakai sebagai bukti situs mati.

Lapisan indexability belum lulus. Sesuai urutan audit, daftar di bawah memprioritaskan akses Google dan keberadaan URL publik. Audit lengkap packaging, isi, schema, dan jaringan tautan ditunda sampai domain produksi dan aturan indeksnya jelas. Temuan berikutnya merupakan persiapan, bukan alasan membuka staging untuk indeks.

## FINDINGS (highest impact first)

### 1. Googlebot dilarang mengakses seluruh domain | Severity: CRITICAL | Type: DECISION

Evidence: `/robots.txt` di situs aktif mengembalikan HTTP 200 dengan isi:

```text
User-agent: Googlebot
Disallow: /

User-agent: *
Allow: /
```

File `public/robots.txt` di repository justru berisi `User-agent: *` dan `Disallow:` kosong. Akar perbedaan antara repository dan respons hosting belum diperiksa di server. Beranda HTTPS mengembalikan 200 dan tidak memiliki meta robots atau header `X-Robots-Tag: noindex` pada respons yang diperiksa.

Why it matters: aturan khusus Googlebot melarang Google mengambil isi halaman, meskipun browser pengunjung bisa membukanya. Status CRITICAL berlaku jika domain ini hendak dipakai menarik pengunjung dari Google. Untuk staging, pemblokiran crawler dapat disengaja. `robots.txt` juga bukan jaminan URL tidak muncul sama sekali dalam hasil pencarian. [Dokumentasi Google](https://developers.google.com/search/docs/crawling-indexing/robots/intro).

Fix: tentukan domain produksi yang akan dipromosikan. Jika domain ini tetap staging, pertahankan pemisahannya dari situs produksi dan gunakan autentikasi atau strategi `noindex` yang bisa dibaca crawler untuk mencegah pengindeksan. Jangan mengharapkan `noindex` terbaca saat Googlebot diblokir. Pada domain produksi yang sudah siap, hapus larangan menyeluruh terhadap Googlebot, izinkan halaman publik beserta asetnya, pertahankan pengecualian halaman privat, dan daftarkan sitemap domain produksi di Search Console. Validasi respons HTTP nyata setelah deploy, bukan hanya file repository.

### 2. Dua alamat untuk toko yang sama sama-sama mengaku URL utama | Severity: HIGH | Type: DECISION

Evidence: `/` dan `/s/toko-utama` sama-sama mengembalikan HTTP 200, komponen `Order/Menu`, business yang sama, 60 produk awal yang sama, dan 14 kategori yang sama. Canonical beranda menunjuk beranda sendiri; canonical `/s/toko-utama` menunjuk `/s/toko-utama`. Canonical berarti penanda alamat utama untuk isi yang sama. Kedua rute memakai `CustomerMenuController::index` di `routes/web.php:25-26`.

Why it matters: setelah crawl dibuka, situs memberi sinyal alamat utama yang tidak konsisten untuk katalog yang sama. Beranda yang sekarang berupa katalog juga belum menyediakan dokumen terpisah untuk tujuan memasarkan aplikasi kepada pemilik usaha.

Fix: untuk tujuan dua audiens yang telah dipilih, usulan struktur adalah `/` untuk halaman aplikasi TokoM dan `/s/{slug}` untuk katalog setiap usaha. Saat isi sudah berbeda, masing-masing boleh memiliki canonical sendiri. Selama beranda masih menduplikasi katalog, pilih satu alamat utama untuk katalog dan samakan canonical, sitemap, serta tautan menuju alamat itu. Jangan mengarahkan katalog semua usaha ke satu canonical. Keputusan yang diperlukan adalah penempatan halaman pemasaran aplikasi; audit ini tidak mengubah rute.

### 3. Detail produk belum memiliki halaman publik tersendiri | Severity: HIGH | Type: DECISION

Evidence: kartu produk pada `resources/js/Components/Customer/CustomerProductCard.jsx:12-14` berupa `article role="button"` yang membuka detail melalui `onOpen`. Detail di `Order/Menu.jsx` berupa modal. Rute `/products` di `routes/web.php` berada dalam grup autentikasi admin. Sitemap yang diperiksa memuat beranda serta Motor Saya, tanpa halaman produk. Muat berikutnya memakai tombol `feed.loadMore` pada `CatalogFeedControl.jsx:7`, bukan tautan halaman publik berikutnya.

Why it matters: nama produk dapat terbaca sebagai bagian katalog, tetapi belum tersedia halaman detail produk yang dapat menjadi hasil pencarian tersendiri. Produk lanjutan juga bergantung pada interaksi tombol. Google tidak mengklik tombol seperti pengguna untuk membuka seluruh isi. [Panduan pagination Google](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading).

Fix: setelah akses indeks siap, sediakan rute publik, misalnya `/s/{shop}/produk/{slug}`, untuk produk yang memang dipublikasikan. Rute wajib tetap membatasi data ke usaha terkait, memberikan 404 untuk produk tidak ditemukan, dan menampilkan data yang sama dengan katalog. Kartu produk perlu tautan `href` ke rute tersebut. Sediakan halaman katalog lanjutan yang punya URL dan tautan biasa, lalu tambahkan URL produk yang valid ke sitemap. Modal dan tombol muat dapat tetap menjadi peningkatan pengalaman pengguna. Keputusan yang diperlukan adalah produk mana yang akan menjadi halaman pencarian publik.

### 4. HTML awal katalog hanya menyediakan kerangka loading | Severity: MEDIUM | Type: DECISION

Evidence: respons HTML awal beranda tidak memiliki H1 maupun tautan `a[href]`; data halaman ada dalam JSON dan konten tampil setelah React berjalan. `resources/views/app.blade.php:59-60` menempatkan JSON dan kerangka loading, sedangkan `resources/js/app.jsx:70` memakai `createRoot` untuk merender aplikasi.

Why it matters: mesin pencari harus menjalankan JavaScript sebelum membaca konten utama dan tautan. Google dapat merender JavaScript, jadi temuan ini bukan bukti bahwa React tidak dapat diindeks atau bahwa situs pasti lambat. Pemblokiran robots pada temuan pertama tetap harus diselesaikan dahulu. [Panduan JavaScript SEO Google](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

Fix: pertimbangkan HTML dari server untuk halaman pemasaran, katalog, dan detail produk publik, menggunakan SSR atau Blade sesuai arsitektur yang dipilih. Judul, deskripsi, isi utama, serta tautan penting perlu tersedia sejak respons awal. Dashboard privat tidak memerlukan perubahan ini demi SEO. Keputusan yang diperlukan adalah cakupan halaman publik dan biaya implementasinya; manfaat kecepatan harus diuji dengan pengukuran sesudahnya.

## THE ONE THING

Tentukan domain produksi dan bereskan akses crawl di domain tersebut. Perbaikan judul, isi, atau schema tidak membuat Google dapat membaca halaman yang seluruhnya diblokir. Jika Hostinger ini hanya staging, lanjutkan persiapan SEO pada domain produksi tanpa membuka staging sembarangan.

## WHAT I COULD NOT CHECK

- **Pengindeksan aktual oleh Google:** belum ada ekspor Search Console Page indexing atau URL Inspection. HTTP 200 dan canonical bukan bukti bahwa URL sudah diindeks. Dibutuhkan hasil Inspection untuk beranda dan satu katalog, termasuk canonical yang dipilih Google serta HTML hasil render.
- **Packaging dan isi secara penuh:** ditunda karena lapisan pertama belum lulus dan halaman pemasaran aplikasi belum tersedia. Dibutuhkan URL produksi yang final, target lokasi toko, dan isi halaman publik kedua audiens. Tidak ada volume pencarian atau perbandingan kompetitor yang diasumsikan.
- **Structured data:** pemeriksaan awal hanya memastikan tidak ada JSON-LD pada beranda yang diambil. Belum dilakukan validasi Rich Results terhadap semua jenis halaman. Dibutuhkan halaman produk/pemasaran final serta data usaha yang benar. Ketiadaan schema tidak otomatis berarti penalti.
- **Internal links seluruh situs:** belum dilakukan crawl menyeluruh untuk membuktikan halaman orphan atau cakupan tiap usaha. Dibutuhkan crawl export yang menyertakan URL, status HTTP, canonical, dan inlinks. Pengamatan kartu/tombol pada temuan 3 terbatas pada katalog yang diperiksa.
- **Performa terkini:** screenshot pengguna menunjukkan Desktop 91 dan Ponsel 77 pada 24 Oktober 2026. Tidak ada laporan yang menjelaskan URL pengujian, LCP, INP, CLS, TBT, atau waterfall. Skor itu tidak diperlakukan sebagai hasil 26 Oktober dan penyebabnya tidak ditebak. Dibutuhkan tautan/laporan PageSpeed Insights untuk mobile dan desktop pada URL produksi yang sama, atau ekspor Lighthouse HTML/JSON. Data pengalaman pengguna nyata dan data simulasi perlu dibedakan. Jika data pengguna nyata belum tersedia, laporkan sebagai belum tersedia.
- **Prioritas berdasarkan trafik:** belum ada Search Console Performance export berisi pages, queries, impressions, clicks, CTR, dan posisi. Urutan di atas berdasarkan hambatan teknis yang terlihat, bukan estimasi kehilangan trafik.
- **Akar konfigurasi robots di hosting:** respons berbeda dari repository, tetapi konfigurasi web server/CDN/file deployment tidak diperiksa. Audit ini tidak menyatakan Hostinger sebagai penyebab tanpa bukti server.

## Catatan bukti awal, bukan kelulusan lapisan berikutnya

- HTTP beranda dialihkan sekali dengan 301 ke HTTPS, lalu 200.
- Sampel `/motor-saya/honda-vario-125-2018` memberi 200 dan canonical yang sesuai. Slug contoh yang tidak ada memberi 404.
- `/login` memberi `X-Robots-Tag: noindex, nofollow`.
- Judul awal beranda staging adalah `Motorku`; setelah React aktif menjadi `Katalog Sparepart - Laravel`.
- DOM beranda staging memuat dua meta description, satu dari Blade dan satu dari Inertia. H1 tidak ditemukan pada beranda yang diperiksa.
- Kode entry frontend mengimpor CSS admin pada semua halaman dan memuat tiga keluarga font. Ini hanya kandidat pemeriksaan payload/font selanjutnya, bukan bukti penyebab skor 77.
- Perubahan merek pada branch `feat/tokom-brand-identity` memperbarui nama bawaan menjadi TokoM dan fallback judul frontend yang sebelumnya Laravel. Itu belum memperbaiki robots hosting, duplikasi canonical, metadata ganda, atau ketiadaan halaman produk publik.
